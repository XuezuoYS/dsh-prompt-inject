# 适配 DSH 0.2.1-rc.2（2026-10-17，已完成）

一句话：插件在新版上**整包不加载**，根因只有一个——新版 dsh 会硬检查插件 `package.json` 的
`engines.dsh`，旧值 `0.2.0-rc.2` 不满足运行时 `0.2.1-rc.2`，于是整个 bundle 在组合阶段被**静默跳过**
（连 loader 行都没有）。host / client 的官方契约 0.2.1 一个都没破坏，改版本声明就活了。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `package.json` | `engines.dsh` → `0.2.1-rc.2`；peer 全部升 `0.2.1-rc.2`（cordis `~4.0.5`）；`dsh.client.inject` 只留 `@deepseek-ai/dsh-client-ui-settings`（primitives 不再是 boot graph 行）。插件自己的 `version` 由用户定为 `0.2.0`（发布号；它只用作版本豁免键 `name@version`，跟加载/兼容判定无关） |

  `application: "applied"`、`changed: false`、无 warning。

- 前后缀注入走 `agent/pre-step`，只在**新的用户轮**触发；本轮是激活前就开始了，所以下一次用户发言才能看到。

## 以后升 dsh 的 checklist

1. 改 `engines.dsh` 成新的精确版本（**别写范围**，这个门槛就是防 rc 之间静默不兼容）。
2. 同步 `peerDependencies` 里的官方包版本（linked 插件的模块路由要靠 peer 表，别精简）。
3. 用 `node .agents/tools/asar2.cjs extract …` 抽一份新包（搭法见 `.agents/checks/README.md` 第二段），
   再用 `node .agents/tools/scan-official-diff.cjs <旧树> <新树>` 圈出变化范围；然后
   `node .agents/checks/run.mjs all` 全绿；最后用 `plugin_manager set_bundle` 让 live 重组合，
   按上面的 4 条验收。只改插件目录的 `package.json` **不会**触发 HMR（不在 watch 列表），
   要动 profile 的 patch/manifest 或从插件页切一次 bundle。

## 留意

- 客户端半仍 `require('@deepseek-ai/dsh-client-ui-primitives')`：0.2.1 起它不再随 app 落盘，只由 web 前端
  `SZ()` 静态模块表（seed）提供；官方实践建议以后自己写控件、别再 require Harness Client 包，属于可选的长期项。
- `%TEMP%\dsh-pi\ok`（0.2.0-rc.2）和 `ok-021`（0.2.1-rc.2）两份解包留着方便复测；仓库 `node_modules\@deepseek-ai`
  是指向 `ok-021` 的 junction（`node_modules/` 已 gitignore）。
- 详细证据在归档里：`archive/2026-10-17-host-compat.md`、`archive/2026-10-17-client-compat.md`；
  目录约定见同级的 `.agents/README.md`。
