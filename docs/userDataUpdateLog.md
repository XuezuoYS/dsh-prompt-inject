# 数据模型更新记录

记 `rules.json` 的结构版本和迁移。现在的结构看 [userData.md](userData.md)。

## v2 — 2026-11-03

从「按注入点排规则」换成「按组排」。

- 顶层 `slots` 换成 `groups`，每个组带名字、开关、模型作用域和 8 个位置块。
- 每个位置块是 `{ enabled, text }`，不再一条规则一个对象；同一个位置改成每组一块文字。
- 组与组之间可以调顺序，这个顺序就是同一位置的拼合顺序。
- 允许零组（`groups: []`），新安装从这里开始。
- 组名输入过程可以为空，保存时回退到上一次保存成功的完整名字（逐字删除的中间值不会覆盖它）。
- 上限改成：50 组、组名 60 字、位置文字 100000 字、一个组 500 个模型键。

迁移（第一次读到 v1 文件）：

- 先复制 `rules.json.v1.bak`，原文件不动。
- 生成一个默认组：`id: "default"`、名字「默认组」、启用、全部模型。
- 每个位置：旧规则的文字按顺序用空行合并（停用规则的文字也并进来）；位置开关看这个位置有没有任意一条旧规则启用。
- v1 文件里如果有更早的 `system.persona`，先拆成 `system.personaHead` / `system.personaTail` 再合并。
- 旧规则各自的模型勾选不保留，统一成全部模型。
- 迁移后的内容在内存里就是 v2；文件在下一次保存时落成 v2。备份确认没问题后可以自己删。

旧客户端：

- v1 的客户端还在 POST `{ revision, slots }` 时，host 回 422 并提示刷新页面。刷新拿到新页面后就能正常保存。
- 新客户端如果传来未知位置键，会直接丢掉并记进 `dropped`，不整包报错。

## v1 — 历史版本

- 结构是 `slots` → `rules`：8 个注入点各一个 `{ rules: [...] }`，每条规则有 `id / enabled / text / models`。
- persona 头尾最早是同一个 `system.persona` 键，后来拆成 `system.personaHead` 和 `system.personaTail`，版本号仍然是 1。
- 那时候的上限是「一个注入点 200 条规则、单条正文 20000 字、一条规则 500 个模型键」。
