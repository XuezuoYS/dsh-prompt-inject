# 注入格式

## 前置词、后置词注入格式

例如，当前有聊天记录：
```
user: user1
ai: ai1
user: user2
ai: ai2
```
假设此插件一直在注入前置词和后置词，则 UI 上一直显示的是去掉前置词和后置词的用户输入，且仅当前用户发送轮是需要注入的，例如将发送给 AI：

| role | content |
| --- | --- |
| system | system content |
| user | user1 |
| assistant | ai1 |
| user | user2 |
| assistant | ai2 |
| user | {前置词}user this input{后置词} |

注意：每轮循环中，工具循环请求不注入 user 前置词和后置词（此轮 user 输入注入需保持直到此轮结束）；user1 \ user2 等历史 user 由于无法实现，不清除前置词与后置词

## 模板字段

规则的正文里可以写官方的提示词变量，发送时会换成这次请求的真实值。设置页每个注入点展开后都有一行字段徽章（点一下就插进输入框），下面一行是注释：

| 字段 | 换成什么 |
| --- | --- |
| `{{model}}` | 这次请求实际用的模型 id，如 `deepseek-flash` |
| `{{provider}}` | 模型属于哪个 provider，如 `deepseek-account` |
| `{{cwd}}` | 当前会话的工作目录绝对路径 |

这三个就是官方 persona 头尾在用的变量（官方头 `You are a coding agent powered by the {{model}} model.`、官方尾 `Your working directory is {{cwd}}.`），值来自官方 agent loop 注册的变量。**「这一步算哪个模型」与规则的作用域匹配走同一条判据**（官方模型选择投影优先，见 [injectScopeAndSetting.md](injectScopeAndSetting.md)）。

渲染时机：

- **用户前置词 / 后置词**：在**注入那一刻**渲染成成品再落进历史。字段当时是多少就是多少，之后不会再变（注入是永久保留的）。
- **system 六个注入点**：在 `system-prompt/assemble` 里渲染，然后把这一段标成 `interpolate: false`——官方的插值器不会再看到我们注入的 `{{`。

认不出来、或这次取不到值的字段（名字拼错、没有 agent 的内部调用、值为空）**原样保留** `{{名字}}`，不报错、也不让这次请求失败；名字不合官方规则（中文、大写等）的一律当字面文本。设置页会对「拼错的小写字段」在卡片里给一条轻提示，保存不拦。

要真的写 `{{model}}` 这几个字（不当字段用），写成 `{{ model }}` 或换个大小写就行——那些都不算字段组，会被原样保留。

字段表是**静态白名单**（就是上面那三个，官方桌面部署注册的变量也就这三个），不去反射官方注册表：名字要给人看、还要配注释。别的插件自己注册的变量插件不认，写在正文里会原样保留。
